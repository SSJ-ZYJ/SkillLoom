# 门禁与测试注册表

门禁把可以机械判断的规则从人工审查里拿走。设计目标是可独立运行、可聚合执行、失败可定位、例外可追溯。测试注册表解决同一类问题的另一半：哪些测试存在、谁负责跑、哪些不进推送门禁。

## 门禁文件约定

| 约定   | 内容                                                                                        |
| ------ | ------------------------------------------------------------------------------------------- |
| 位置   | `scripts/gates/`，一个关注点一个文件                                                        |
| 命名   | `check-<关注点>.ts`，关注点用名词，不用 `check-all`                                         |
| 入口   | `if (import.meta.main)` 下执行，函数可被单元测试导入                                        |
| 输出   | 通过时打印一行计数摘要，失败时逐条打印 `文件:行: 原因`                                      |
| 退出码 | 只在存在失败时设 `process.exitCode = 1`，不提前中断其他检查                                 |
| 范围   | 由 `git ls-files --cached --others --exclude-standard` 决定，覆盖已跟踪与未忽略的未跟踪文件 |

检查范围统一走 Git 文件清单，避免手写目录遍历。构建输出、依赖目录与带日期的过程材料用精确前缀排除，不扩大忽略范围。

## 聚合执行

聚合器维护一个数组，每项包含名称、命令与是否实时输出。执行顺序遵循三条规则：

1. 格式与静态检查在前，单元测试在中，生产构建在最后。
2. 单项失败不中断后续项，结束时汇总全部失败项。
3. 前置项失败时跳过构建，并打印跳过原因。

诊断密集的检查实时输出，常规检查捕获输出后只打印首行摘要与耗时。快速入口只跑检查，完整入口在全部检查通过后再构建。

## 阈值配置

源码、样式、测试文件与函数的软硬阈值写在配置文件里，文档行数阈值按路径在检查脚本中判定。

```json
{
  "limits": {
    "source": [300, 500],
    "css": [400, 600],
    "test": [400, 700],
    "function": [60, 100]
  },
  "exceptions": {
    "path/to/file.ts": {
      "ceiling": 560,
      "reason": "2026-11-17: 说明对象、保留职责与移除条件。"
    }
  }
}
```

数组第一位是建议上限，第二位是硬上限。超过建议上限输出 REVIEW，不阻断。超过硬上限失败，除非登记了例外。

## 例外规则

例外是审查记录，不是提限许可。登记项必须同时满足：

- 有非空原因，以日期开头，说明保留职责与移除条件。
- `ceiling` 等于当前实际大小，不预留增长空间。
- 当前大小确实超过硬上限。
- 文件或函数仍然存在。指向不存在对象的例外会让检查失败。

增长或缩减都要更新 `ceiling`。回到硬限以内时删除例外。数值变化由 Git 历史承载，原因里不记录每次调整。

## 预警分级

| 级别     | 条件                                        | 处理                 |
| -------- | ------------------------------------------- | -------------------- |
| REVIEW   | 超过建议上限、未超硬上限                    | 输出供审查，不阻断   |
| NEAR     | 距硬上限不足上限的 5%，小阈值至少 10 个单位 | 按剩余量升序输出     |
| AT LIMIT | 剩余不超过 2 个单位                         | 单独标记并在汇总计数 |

已登记有效例外或硬限不设上限的项不计入预警。

## 内容量算法

中文没有空格分词，按字符计数：每个 Unicode Han 字符计一单位，连续的字母、数字、下划线整体计一单位，标点和空白不计。代码块、链接与表格按原始文本统计。该算法用于堵住超长单行绕过行数限制，不等同阅读时长。

函数行数由 TypeScript AST 识别，工厂函数包含内部嵌套函数，不自动扣减。函数标识由名称加同名遍历序号组成，重命名或调整顺序后需要重新审核基线。

## 测试注册表

表格是测试范围的唯一声明。列定义：

| 列       | 含义                               |
| -------- | ---------------------------------- |
| Scope    | 仓库相对路径，可含 `*` 通配符      |
| Level    | `unit`、`module`、`system`         |
| Runner   | `bun-test`、`playwright`           |
| Args     | 该范围固定的执行器参数，没有写 `—` |
| Metadata | 逗号分隔的属性，含义在下一张表定义 |

层级判定：不启动浏览器、不读仓库外状态的纯逻辑为 `unit`；跨模块、读仓库数据、写临时目录或验证导出接口为 `module`；生产构建上的浏览器行为为 `system`。

## 元数据双向核对

每个属性都要有机械证据，证据与声明互相约束：

| 属性       | 证据                                           |
| ---------- | ---------------------------------------------- |
| `browser`  | Runner 必须是 `playwright`                     |
| `isolated` | 范围内文件包含 `mkdtempSync(`                  |
| `scene`    | 范围内文件包含 `@cinematic`                    |
| `snapshot` | 文件包含 `toHaveScreenshot(`，且基线目录含 PNG |

声明属性却没有证据会失败，出现证据却没有登记属性同样失败。核对逻辑由注册表模块提供，执行器与检查器共用同一份解析代码，不维护第二份清单。

## 执行计划

执行计划读取注册表，生成文件清单与命令。对外提供两个子命令：`list <层级>` 只打印计划，`run <层级>` 执行。范围筛选用元数据开关表达，例如 `--scene`、`--snapshot`、`--no-snapshot`、`--live`，其余参数原样传给底层执行器。

CI 不直接写测试路径，而是调用同一入口的 `*:ci` 命令，再用 `--` 追加分片与基线参数。分片只切分用例，不跳过断言。分片数变化后需要同步更新 required checks。

## 新增检查的完整步骤

1. 写 `scripts/gates/check-<关注点>.ts`，导出可测试的纯函数。
2. 加单元测试，覆盖通过、失败与边界三类输入。
3. 接入聚合数组，确定位置与是否实时输出。
4. 在 `package.json` 声明命令，命名与文件职责一致。
5. 确认命令入口检查覆盖新脚本路径。
6. 更新 `scripts/AGENTS.md` 的职责表与根入口的验证矩阵。
7. 运行聚合入口，确认失败时能定位到文件与行。

## 命名示例

- 聚合器：`scripts/gates/run-gates.ts`，快速入口 `check:fast`，完整入口 `check`。
- 阈值实现：`scripts/gates/check-budgets.ts`，配置 `scripts/gates/quality-budgets.json`。
- 文档检查：`scripts/gates/check-docs.ts`，同时校验链接与禁用表述。
- 注册表核对：`scripts/gates/check-test-registry.ts`。
- 注册表与执行：`scripts/tests/test-registry.ts`、`scripts/tests/test-plan.ts`。
- 注册表文档：`docs/testing/README.md`。
