# 在新仓库建立规范

按阶段推进，每阶段都能独立产生收益并验收。一次铺满会产出成批无入口文档，维护成本高于收益。

前置条件：仓库已有稳定的目录结构、格式工具和测试命令。结构还在每天变动时，先固定结构，再写入口文件。

## 阶段一：术语与行文

目标：统一用词，消除同一概念的多种写法。

产出：

1. `docs/terminology/terms.md`，含术语表、缩写表、用词改写表。
2. `docs/terminology/README.md`，写范围与维护流程。
3. 一份行文规则，覆盖空格、标点、语气与结构。

做法：从现有文档提取高频概念，只收录已出现分歧的词。术语表不求全，先覆盖项目名、核心对象、代码类名与正文用词的对应关系。

验收：

- 新增一个概念时，能在表里找到唯一写法。
- 审查能指出某句违反了哪一条，而不是“感觉不对”。
- 术语表条目有约束列，可判断合规与不合规。

常见失败：把术语表写成词典，只有解释没有约束；收录过多通用技术词，维护量超过收益。

## 阶段二：根入口

目标：任何人或 Agent 进入仓库，读一份文件就知道边界与流程。

产出：根 `AGENTS.md`，包含仓库布局、运行入口、修改流程、约定、事实依据表、验证矩阵。

做法：先写目录树与验证矩阵，这两节最能减少误操作。约定按主题分组，每组三到六条，只写无法从源码直接读出的约束。

验收：

- 新增一类文件时，能从“扩展去向”判断放在哪里。
- 改动完成后，能从验证矩阵查到要跑哪些命令。
- 每条约定都能回答“违反了会怎样”。

常见失败：把 README 内容搬进入口文件；复制完整命令表，命令变更后出现两个版本；条目写成愿望，没有可执行判据。

## 阶段三：目录入口

目标：改某个目录时，只读该目录入口就能定位文件与本地约束。

产出：按改动频率排序，先给最常改的两三个目录写 `AGENTS.md`，不要求全仓库覆盖。

做法：目录树只列到二级，文件级信息放职责表。表里每行一句话说明职责，不写实现方式。末尾写新增文件的归类规则与门禁接入要求。

验收：

- 目录入口不超过 120 行。
- 树与仓库实际结构一致。
- 新增文件后知道要更新哪张表。

常见失败：全仓库铺开，一半目录入口三个月后过期；子目录入口重复全局规则，规则变更时改多处。

## 阶段四：格式与静态检查

目标：把风格争议交给工具，审查只讨论设计。

产出：格式化工具配置、Lint 配置、类型检查命令，以及对应的 `*:check` 命令。

做法：格式化与 Lint 分成两个命令，不互相代替。Markdown 与代码使用不同工具时，明确各自范围。编码与行尾写入编辑器配置与 Git 属性文件。

验收：

- 格式检查失败时，输出可直接定位文件。
- 格式通过不被当成 Lint 通过。
- 新增文件自动纳入检查范围，不需要维护文件清单。

## 阶段五：自有门禁

目标：把项目特有的结构约束变成可执行检查。

产出：`scripts/gates/` 下的检查脚本、聚合入口、命令声明。

做法：只写两条最能防止回归的检查。常见选择是导入方向与文档链接。一条检查只回答一个问题，输出定位到文件与行。

验收：

- 单条检查可独立运行，也可被聚合入口调用。
- 故意引入违规时检查失败，恢复后通过。
- 聚合入口在单项失败时继续执行其余项，并汇总失败。

常见失败：一条脚本检查五件事，失败时无法判断原因；检查没有测试，规则变更后静默失效；新增脚本未接入聚合入口，成为无入口文件。

## 阶段六：测试注册表与阈值

目标：测试范围与文件规模有唯一声明，新增内容自动进入检查。

产出：测试注册表文档、注册表核对脚本、执行计划入口、阈值配置。

做法：注册表按目录范围登记，不逐文件登记。元数据必须有机械证据，声明与证据双向核对。阈值先只设文件行数，稳定后再加函数与文档内容量。

验收：

- 新增测试文件放入已登记目录即被纳入执行计划。
- 删除测试文件后，注册表核对失败并提示对应行。
- 超过硬上限时检查失败，例外必须写原因与移除条件。

常见失败：注册表与执行脚本各维护一份清单；元数据只是标签，没有证据核对；阈值为通过检查而调高。

## 阶段顺序的依据

术语与行文的成本最低，且后续所有文档都受益。根入口决定其他文件的写法，必须先于目录入口。格式检查稳定后，自有门禁才有可信的比较基线。测试注册表依赖稳定的目录结构与执行命令，放在最后。

每个阶段结束后运行一次全量检查，确认新规则没有把存量问题一次性引爆。存量超限登记精确例外，不在阶段切换时批量重构。

## 团队推行

- 规则变更与代码变更同一提交，审查者核对规则条文是否有实质变化。
- 新增检查前先确认现有检查能否扩展，避免同一关注点两份实现。
- 规则失效时修改规则，不用 suppress、忽略或跳过维持表面通过。
- 每季度核对一次目录树与实际结构。入口文件过期比缺失更有害。

## 阶段落地核对

每阶段完成后核对四项：

- 新规则有唯一维护处，其他文件只链接。
- 新增文件已在上级目录树登记。
- 对应检查已接入聚合入口或测试注册表。
- 全量检查通过，存量超限已登记精确例外。
