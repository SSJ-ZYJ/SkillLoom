# 行文与术语

规范文本的价值取决于可核对性。同一概念换一个词、同一事实写两遍、用程度词代替数量，都会让读者无法判断哪句是约束。本文件给出可执行的写法与术语表维护流程。

## 空格与标点

| 场景                         | 写法                                               |
| ---------------------------- | -------------------------------------------------- |
| 汉字与半角字母、数字、单位   | 空一格：`Nuxt 4`、`3100 端口`、`1000 upem`         |
| 数字与百分号、度号           | 紧贴：`40%`、`90°`                                 |
| 版本号、路径、命令、标识符   | 内部不插空格                                       |
| 行内链接与左右文字           | 空一格：`详见 [终端接口](#终端接口) 文档。`        |
| 链接紧邻标点、括号、行首行尾 | 不加空格：`见（[字体](#字体)）。`                  |
| 行内代码、加粗、斜体         | 只按中西文规则处理，不加额外空格                   |
| 中文正文标点                 | 全角，前后不留半角空格                             |
| 中文引号                     | 双引号“内容”、单引号‘内容’，不用直角引号或英文引号 |
| 标题的 `#`                   | 后恰好一个空格，`#` 不算中西文间距对象             |
| 日期、时间、区间             | `2026-10-25`、`14:30`、`100–900`，数字一律半角     |

分号与冒号只在确有并列或说明关系时使用。一句里出现两处以上分号或冒号时先拆分。独立的意思用句号分开，不串联成长句。中文注释按独立句断句，不沿用英文注释的分号结构。

## 用词与语气

- 禁止比喻、营销表达和无法核实的模糊描述。能写对象、数量、条件或结果时，不写程度词。
- 不写“我们”“你可以”等对话口吻。规范条文用祈使句或“必须/应当/可以”，事实用陈述句。
- 未知写“未验证”并给出验证方式，不写“可能”“大概”“未来会支持”。
- 不用“首先/其次/最后”制造结构。段落按事实关系组织。
- 加粗与“必须”只留给改变行为的分句。处处强调等于没有重点。
- 英文词不接中文词缀。有对应中文词时不用英文词充当词根。
- 写“边界”“形态”“内容划分”前先确认能否点名具体对象。能点名时写具体字段、结构、流程或分工。

禁用词与改写对照只维护一处。新增禁用词先补对照表，再在全仓库生效。

## 结构

- 每篇一个一级标题，标题层级连续，不跳级。标题写主题，不写“概述”“其他”。
- 先结论后依据。段落一个主题，列表只放并列项，步骤用编号。
- 一段只讲一件事。超过三句或需要回看的段落按主题拆开。
- 表格用于对比和映射。代码块标注语言。命令、路径、符号用行内代码。
- 仓库内链接用相对路径，外部链接用完整 URL。链接文字说明目标，不写“点击这里”。
- 不写本机盘符路径与用户目录。指向仓库外资源时写远端地址，指向本地检出时写占位符。
- 不重复其他文档的规则和清单，用链接指向唯一维护处。
- 文档元数据用英文书写，正文保持中文。状态写在标题下一行，取值如 `Status: adopted`、`Status: historical`。
- 计划、审计、验证快照写明日期，不写成长期规范。
- 正文不写“已实现”“即将支持”。状态由源码、脚本和门禁承载。
- 现行事实不写日期和时间。

## 术语表的三个文件

| 文件             | 职责                               |
| ---------------- | ---------------------------------- |
| `README.md`      | 适用范围、文件分工、维护流程       |
| `terms.md`       | 术语表、缩写表、用词与改写对照     |
| `translation.md` | 界面文案、内容文件与译名的对应规则 |

`README.md` 只写流程与范围，不重复表内容。`terms.md` 是术语、缩写与禁用词的唯一来源。`translation.md` 只写双语对应关系，译名仍指向 `terms.md`。

## 术语表结构

三列，缺一列就会退化成词典：

| 列         | 写法                                   |
| ---------- | -------------------------------------- |
| 术语       | 规范写法本身，保留官方大小写           |
| 全称或解释 | 只在表内展开一次，正文首次出现不展开   |
| 使用约束   | 写“正文写什么”“不写什么”，给可执行判据 |

收录范围：

- 项目名、产品名与组织名，以及容易写错的大小写和连字符。
- 技术专名的官方写法，例如框架、格式、协议、数据库。
- 代码类名与正文用词的对应关系，例如 `Session` 与“会话”。
- 中文易混概念，例如认证与授权、账户与成员资格。
- 被替换的旧说法与新说法。

约束列写判据，不写偏好。对比“尽量使用中文”与“正文写‘会话’，`Session` 只指代码类”，后者可以机械判断。

## 缩写表

缩写单独成表，三列：缩写、全称、使用约束。全称只在此表维护，正文只写缩写，不展开。目录名、包名、命令中的大小写以实际标识符为准，与正文写法分开记录。

## 用词改写表

两列：不写、改写为。每行给出可替换的目标表达，而不是“避免空泛”这类要求。改写目标必须能直接写进句子。

维护规则：

1. 新词先入表，再修改正文。同一批改动里同时完成。
2. 一个概念只留一个规范词，旧词从正文删除，不在表里保留“也有人说”。
3. 表内条目按主题分组，不按发现顺序追加。
4. 术语或译名变化时同步修改受影响文案，再运行格式与阈值检查。

## 双语规则

- 两份 locale 的键和插值参数必须一致。新增文案先写中文再补英文，同一提交完成。
- 译名以 `terms.md` 为准。概念用中文规范词，代码类名保留英文，固定材质名中英一一对应。
- 缩写在两种语言中都写缩写，不展开全称。
- 中文文案用全角标点并遵守汉字间距，英文文案用半角标点。数字一律半角。
- 页面正文与元信息维护在内容文件，不在 locale 重复存放。成对正文按行对应，行数、行类型与占位符逐行一致。

## 验证

| 检查            | 覆盖                              |
| --------------- | --------------------------------- |
| `format:check`  | 空格、标点、表格与换行的机械格式  |
| `check:docs`    | 内部链接目标存在、禁用表述不出现  |
| `check:budgets` | Markdown 行数与内容量             |
| `bun test app`  | locale 键与插值一致、成对正文结构 |

术语一致性、事实准确性与约束列的可执行性由人工核对。机械检查通过不代表表述正确。
