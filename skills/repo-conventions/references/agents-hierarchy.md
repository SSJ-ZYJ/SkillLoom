# AGENTS.md 分层

`AGENTS.md` 是给 Agent 的入口文件，不是完整手册。它回答四件事：这个目录有什么、每个文件负责什么、改动时读哪份专题文档、怎么验证。细节一律外链，正文只保留无法从源码直接读出的约束。

## 三层职责

| 层级     | 位置                    | 只放                                                           | 不放                                       |
| -------- | ----------------------- | -------------------------------------------------------------- | ------------------------------------------ |
| 根入口   | 仓库根 `AGENTS.md`      | 跨目录约束、仓库布局、运行入口、修改流程、验证矩阵、事实依据表 | 单个模块的实现细节、命令清单副本、阈值数值 |
| 目录入口 | `<目录>/AGENTS.md`      | 本目录注释树、文件职责表、本地例外、扩展去向                   | 重复的全局规则、其他目录的职责             |
| 专题文档 | `docs/architecture/` 等 | 现行接口、架构、决策取舍                                       | Agent 指令、过程记录                       |

根入口是唯一强制全仓库遵守的文件。子目录入口只补充该目录的特殊约束，冲突时以根入口为准，并在子目录入口写明这一句。

## 根 AGENTS.md 骨架

按以下顺序组织，章节缺失要有理由。

```text
# <项目名> — Agent 工作规范

一句话定位，加需要先读的文档列表（带链接与一句话职责）。

## 仓库布局
带注释的目录树。每个顶层目录一行注释，不展开到文件级。
末尾写“扩展去向”：新增路由、组件、脚本、正文分别放哪里。

## 运行入口
启动、检查、构建命令指向 package.json，不复制完整命令表。
写明端口、复用规则、异常处理边界。

## 修改流程
编号步骤：读规范 → 定位调用链 → 最小修改 → 执行检查 → 报告结果。
写明禁止事项：不清理工作区、不擅自 commit、不用 suppress 掩盖缺陷。

## 约定
按主题分组：组织规范、标识与范围、工具链、分层职责、
共享 UI、安全、交互、字体、无障碍、双语、敏感数据。
每组三到六条，每条自包含。

## 事实依据
表格：事项 → 来源文件。用于回答“这个说法以什么为准”。

## 格式、规模阈值与验证
格式工具与规则一句话，阈值数值指向唯一维护处。
验证矩阵：改动类型 → 需要执行的检查。

## 文档与交付
文档放置规则、提交规范、完成前的核对项。
```

## 子目录 AGENTS.md 骨架

````text
# <目录名> 结构

一句话适用范围，加“修改本目录前读本文件”。
加门禁分级、测试层级等上级文档的链接。

```text
<目录>/
  <子目录>/   职责一句话
  <子目录>/   职责一句话
```

## <子目录>/

| 文件 | 职责 |
| --- | --- |
| file-a.ts | 单一职责描述，不写实现方式 |
| file-b.ts | 同上 |

（有多个子目录时重复本节。）

新增文件先归入现有目录。新增目录须同步本文件与根目录树，
并接入门禁聚合或测试注册表，否则检查不覆盖新入口。
````

## 行数阈值

| 文件               | 建议上限 |       硬上限 |
| ------------------ | -------: | -----------: |
| 根 `AGENTS.md`     |   200 行 |       250 行 |
| 子目录 `AGENTS.md` |   100 行 |       120 行 |
| 其他 Markdown      |   500 行 | 不设行数硬限 |

超过建议上限先压缩或迁移细节。硬上限只在登记精确上限与原因后突破，登记位置是 `scripts/gates/quality-budgets.json`。规则文件不为了行数把一条约束拆到两个文件。

## 同步规则

改代码时同步改入口文件，属于同一次提交：

- 新增或移动文件：更新所在目录的文件职责表。
- 新增或删除目录：更新根目录树与该目录入口的注释树。
- 新增专题文档：先在根入口的文档列表与 `docs/AGENTS.md` 的目录树登记，再写作。
- 新增检查脚本：更新 `scripts/AGENTS.md` 的职责表，并接入门禁聚合。
- 删除能力：删除对应条目，不保留“已移除”说明。

注释树用两空格缩进，目录名后跟 `/`，注释与目录名之间用空格分隔，不画竖线。树只列到二级目录，文件级信息放职责表。

## 写作要点

- 每条自包含。读者只看一条也能判断怎么做，不依赖上一条的上下文。
- 用祈使句或“必须/应当/可以”。事实用陈述句。
- 不写“详见某文档”作为唯一内容。要么给出可执行约束，要么删除。
- 不复制阈值数值、命令定义和依赖版本。这些各有唯一维护处，入口文件只链接。
- 不写实现过程、历史沿革和“为什么当初这样做”。取舍写进 ADR，过程写进 `.agents/notes/`。
- 目录树必须与实际一致。树过期比没有树更危险。

## 落地示例

- 根入口：`AGENTS.md`，含仓库布局、修改流程、验证矩阵与事实依据表。
- 目录入口：`scripts/AGENTS.md`、`docs/AGENTS.md`。
- 专题入口：模块改动读对应架构文档，例如 `docs/architecture/<模块>.md`。
- 行数阈值与例外：阈值配置文件。
