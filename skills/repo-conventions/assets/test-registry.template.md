# 测试注册表与执行计划

Status: adopted

本文件是测试层级、执行器与执行参数的唯一依据。仓库中的测试文件是实际内容，注册表检查双向核对表格与仓库：表格声明的范围必须存在，仓库中的测试文件也必须登记。测试命令由执行计划读取本表生成，CI 调用同一入口。

## 层级

| 层级   | 范围                                                 | 执行器            |
| ------ | ---------------------------------------------------- | ----------------- |
| unit   | 单个模块或少量纯函数，不启动浏览器，不读取仓库外状态 | `bun test`        |
| module | 跨模块、仓库数据、临时文件目录或模块导出的接口       | `bun test`        |
| system | 生产构建上的浏览器行为                               | `playwright test` |

## 注册表

Scope 为仓库相对路径，可含 `*` 通配符。Args 记录该范围固定的执行器参数，没有时写 `—`。Metadata 为逗号分隔的属性，含义见下一节。

| Scope                              | Level  | Runner     | Args | Metadata          |
| ---------------------------------- | ------ | ---------- | ---- | ----------------- |
| src/features/<模块>/core/*.test.ts | unit   | bun-test   | —    | —                 |
| src/features/<模块>/*.test.ts      | module | bun-test   | —    | —                 |
| scripts/gates/*.cli.test.ts        | module | bun-test   | —    | isolated          |
| tests/e2e/<场景>/*.spec.ts         | system | playwright | —    | browser           |
| tests/e2e/visual/*.spec.ts         | system | playwright | —    | browser, snapshot |

## 元数据

| 名称     | 含义                                       | 机械核对                                       |
| -------- | ------------------------------------------ | ---------------------------------------------- |
| browser  | 需要生产构建与无头浏览器                   | Runner 必须为 `playwright`                     |
| isolated | 每个用例写独立临时目录，不读写共享状态     | 范围内文件包含 `mkdtempSync(`                  |
| scene    | 包含依赖 GPU 或长时序的用例，推送门禁排除  | 范围内文件包含 `@cinematic`                    |
| snapshot | 与图片基线比对，基线属于渲染它的机器       | 文件包含 `toHaveScreenshot(`，且基线目录含 PNG |
| live     | 需要真实外部依赖的联合验证，不进入普通分片 | 用例名称包含 `@live`                           |

属性与文件内容双向核对：声明了属性却没有对应证据会失败，出现证据却没有登记属性同样失败。

## 执行

| 命令                  | 计划                                      |
| --------------------- | ----------------------------------------- |
| `bun run test`        | unit 与 module，先读取注册表生成文件清单  |
| `bun run check:tests` | 只运行注册表一致性检查                    |
| `bun run test:e2e`    | 生产构建后运行 system，排除场景与快照范围 |
| `bun run test:scene`  | 生产构建后只运行场景范围                  |
| `bun run test:visual` | 生产构建后只运行快照范围                  |

`list <层级>` 只打印文件与命令，`run <层级>` 执行。分片参数传给底层执行器，CI 与本地使用同一入口。

## 维护

新增测试文件放入已登记的范围即被登记。新增目录、层级或执行器时，先在本表增加一行，否则注册表检查失败。删除测试文件后同步删除没有文件的表格行，或改由合法通配符覆盖。执行器与检查器共用注册表模块的解析逻辑，不维护第二份清单。
