# 术语、缩写与用词对照

适用范围：全仓库 Markdown 与产品文案。项目名、产品名与技术专名保留官方英文写法，普通概念用中文。代码标识符保留英文大小写，叙述概念时用对应中文词。全称与解释只在本表维护，正文首次出现不展开。禁用词与改写也在此维护。

维护流程：新概念、新译名或新的禁用词先补本表，再在正文使用。一个概念只用一个词，不混用缩写、全称或中英文变体。

## 术语表

| 术语           | 全称或解释    | 使用约束                                   |
| -------------- | ------------- | ------------------------------------------ |
| <项目名>       | <官方全称>    | 正文只写 <项目名>                          |
| <核心对象>     | <一句话定义>  | 正文写“<中文词>”，`<ClassName>` 只指代码类 |
| <技术专名>     | <用途>        | 保留官方大小写，不写 <错误写法>            |
| <易混概念 A>   | <与 B 的区别> | 与 <概念 B> 区分，不互换                   |
| <被替换的说法> | <原含义>      | 改写为 <规范词>                            |

收录标准：

- 项目名、组织名与容易写错的大小写、连字符。
- 框架、格式、协议、数据库的官方写法。
- 代码类名与正文用词的对应关系。
- 中文易混概念。
- 已被替换的旧说法。

约束列必须能判断合规与不合规。对比“尽量用中文”与“正文写‘会话’，`Session` 只指代码类”，后者可执行。

## 缩写对照

| 缩写   | 全称或解释               | 使用约束                       |
| ------ | ------------------------ | ------------------------------ |
| <缩写> | <英文全称>（<中文全称>） | 正文只写缩写                   |
| <缩写> | <英文全称>               | 保留官方大小写，不翻译、不展开 |

正文只写缩写，全称只在本表出现。目录名、包名、命令中的大小写以实际标识符为准，与正文写法分开记录。

## 用词与改写

禁用比喻、营销表达和无法核实的模糊描述。能写对象、数量、条件或结果时，不写程度词。以下替换适用于全仓库 Markdown、产品文案与注释。

| 不写                | 改写为                 |
| ------------------- | ---------------------- |
| <空泛词>            | <具体对象、数量或动作> |
| <营销词>            | <可核对的能力或指标>   |
| <英文词 + 中文词缀> | <中文词>               |
| <模糊量词>          | <精确数量或完整枚举>   |

改写目标必须能直接写进句子。只要求“避免空泛”而不给替换词，无法执行。

英文词不接中文词缀。有对应中文词时不用英文词充当词根。
