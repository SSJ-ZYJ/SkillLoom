## 修改流程

1. 阅读本文件及任务相关源码、配置、文档。检查分支与 `git status --short`，保护未提交修改和未跟踪文件。
2. 定位真实调用链，明确根因、范围、依赖和验证方式。
3. 最小化修改并复用现有实现。禁止重复状态源、无意义抽象、为行数拆文件与无依据的新依赖。
4. 执行适用检查，审查 Diff，同步测试与文档。如实说明失败与未覆盖范围。
5. 不得用 suppress、`any`、跳过测试或扩大忽略掩盖缺陷。
6. 不得自行清理工作区、重置或覆盖他人改动。未经明确要求，不执行 commit、push、rebase 或修改历史。

## 格式、规模阈值与验证

遵守 EditorConfig、Git attributes、Biome、Prettier。UTF-8、LF、两空格、双引号、分号、末尾换行。

源码注释使用双语，英文在上、中文在下，每条一句话，不复述代码。

`lint` 与 `format:check` 独立，不得把格式通过说成 Lint 通过。Lint 无 error、硬上限与例外、软阈值审查的分级执行以 `docs/architecture/engineering-quality.md` 为唯一规范。

| 改动                 | 验证                               |
| -------------------- | ---------------------------------- |
| Markdown、YAML、翻译 | 格式、文档阈值、链接检查、双语一致 |
| TS、架构、检查脚本   | 类型、单测、架构及阈值检查         |
| CI、命令入口         | 入口路径检查、对应工作流运行       |
| UI 与样式            | 相关单测、E2E、浅色与深色主题回归  |
| 依赖与构建配置       | 类型、生产构建、开发与预览启动     |

重要改动执行完整检查与端到端测试，或明确报告阻塞和未覆盖范围。自动化结果不等同用户最终视觉验收。

## 文档与交付

- 根入口只放全局约束和入口，模块例外确有需要才下沉。
- 每个 `AGENTS.md` 包含所在目录的结构介绍：注释目录树、文件职责与扩展去向。新增或移动文件时同步更新。

- 完成前核对 Diff 与 `git status`，交付修改原因、文件、实际验证结果、失败和遗留风险。
- 只有明确请求才提交，提交信息使用 Conventional Commits。测试与实现同笔提交。
