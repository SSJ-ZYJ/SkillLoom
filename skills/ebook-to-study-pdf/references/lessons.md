# 两类既有项目的经验

这些经验提炼自大学物理下册和计算机网络的结构清单、笔记索引、LaTeX 构建及会话要求；不附教材或私人会话，不把特定章节/页码硬编码成规则。

## 扫描教材

旧扫描源存在漏扫，章节内印刷页偏移逐段变化，缺失位置包括章首页、公式推导和习题续文。较完整版本提供了恢复依据。正确流程是核对页眉和正文衔接、登记版本映射、把缺失教学内容补进当前真源、再构建验证；不是盲目维持旧 Markdown，也不是只改生成的 TeX。附录前几章的答案页不应误记为末章习题缺页。

## 有书签/文字层的教材

章节书签足以提出切分边界，却不能证明文字层中文准确。抽取中文和中英混排有错误，因此引用、公式及图表以视觉页为准。原生候选与扫描/OCR 衍生件必须区分“文件结构”与“文字可信度”。

本次用新诊断脚本检查了两份实际源文件：物理完整版 482 页中 473 页被标记为图像扫描候选（无抽取文字），另 9 页为文字对象候选；网络教材 505 页均有隐藏文字线索，第一章首页的图片覆盖率为 1.0，视觉原页可读而抽取中文明显错误。这纠正了旧清单中仅凭书签/文字层称网络源为“数字版”的表述；诊断结论是扫描/OCR 高风险来源，不是完成了全书内容审校。

## 对两个项目共同有效

- 最初的笔记仅定位原书，后来改为离开原书也完整的学习材料：每章学习目标，题目/解析/答案分明。
- Markdown 适合代理辅导和内容更新，LaTeX/PDF 必须实际保留并交付，不能仅改 Markdown。
- 总结应压缩冗余，不要近似复刻原书体量；也不能为了薄而删必要题干。
- Noto Serif 正文、Noto Sans 标题、浅色语义框比简单黑白长段落更便于阅读。
- Pandoc 的 HorizontalRule 会产生无意义分割横线；应从真源与过滤器解决，不靠 PDF 后处理遮住。
- 更晚的要求简化封面为课程名，去掉学习笔记等冗余字样；模板按这一约定默认处理。
- 构建失败、长时间不透明进程、输出 PDF 锁定都要看具体日志/占用，不能把长等待当成执行成功。

本 Skill 的 `inspect`、全页切分验证、manifest 双真源模式和临时目录构建把这些风险变成显式检查点。自动脚本不宣称能完成教材内容理解、OCR 纠错或视觉审美；这些仍由执行代理依据实际页面完成。
